──────────────────────────────────────────────────────────────
  ELIA — Chef de Projet + ETL & Airflow
──────────────────────────────────────────────────────────────

Phase 1 — Environnement
  - Installer Apache Airflow (local, Python)
  - Installer PostgreSQL → créer la base weather_madagascar

Phase 2 — Extraction API (Open-Meteo)
  - Écrire extractor.py
      · Appel current  : temperature_2m, humidity, precip, wind, pressure
      · Appel hourly   : mêmes variables
      · Appel daily    : temp max/min, precip_sum, wind_max, uv_index_max
  - Stocker la réponse brute JSON → table weather_raw

Phase 3 — Transformation & Nettoyage
  - Écrire transformer.py
      · Parser le JSON brut depuis weather_raw
      · Valider/nettoyer les valeurs (nulls, types, unités)
      · Insérer → weather_clean
      · Calculer agrégations journalières → weather_daily

Phase 4 — Rapports & Alertes
  - Écrire reporter.py
      · Rapport météo par location et par jour → weather_report
      · Logique alertes simples → table alerts

Phase 5 — DAG Airflow
  - Créer weather_etl_dag.py
      · Tâche extraction current (toutes les heures)
      · Tâche extraction hourly/daily (une fois par jour)
      · Tâche transformation, agrégations, rapports, QA
      · Dépendances entre tâches, retries, alertes d'échec

  + Coordination générale de l'équipe (rôle CP)

──────────────────────────────────────────────────────────────
  AMBOARA — Données Statiques (fichiers de référence)
──────────────────────────────────────────────────────────────

Ces fichiers sont créés UNE SEULE FOIS et chargés en base
au démarrage (par le script seed de Manoa).

  1. regions_madagascar.csv
       22 régions : id, nom_region, chef_lieu,
       latitude, longitude, altitude, climate_type_id

  2. weather_locations.csv
       22 stations (1 par région) : id, nom_station,
       region_id, latitude, longitude, altitude, timezone_id

  3. climate_types.txt
       Types de climat : Tropical humide, Semi-aride,
       Tempéré, etc.

  4. timezones.csv  (en dur)
       Ex : Indian/Antananarivo, UTC+3

  5. api_sources.json
       Open-Meteo : base_url, api_type, is_active

  6. units.json + variables.json
       Unités : °C, %, mm, km/h, hPa…
       Variables : temperature_2m, precipitation, wind…

  7. weather_thresholds.json  (en dur)
       Seuils : ex. temp > 35°C = alerte chaleur

  8. alerts_types.json  (en dur)
       Types : chaleur, pluie intense, vent fort…

  Livraison attendue AVANT que Manoa lance le script seed.


──────────────────────────────────────────────────────────────
  MANOA — Schema SQL + Config + Seed + QA
──────────────────────────────────────────────────────────────

1. schema.sql — Création de la base de données
     Tables MVP :
       - regions, weather_locations
       - weather_raw, weather_clean, weather_daily
       - weather_report, api_sources, alerts, data_quality
     Clés primaires, clés étrangères, index

2. config.yaml — Configuration du pipeline
     - URLs API Open-Meteo (current, hourly, daily)
     - Intervalles d'exécution (1h / 24h)
     - Paramètres DAG (retries, timeout)
     - Credentials DB (via .env)

3. Script seed — Chargement initial des données statiques
     - Charger tous les fichiers d'Amboara en BDD
     - Vérifier intégrité des clés étrangères
     - Log : N lignes insérées par table

4. quality.py — Contrôle qualité
     - Vérifier valeurs hors plage (temp, humidité, pression)
     - Détecter les nulls inattendus après transformation
     - Logger les anomalies → table data_quality

  Manoa est le pivot entre Elia (ETL) et Jemima/Valisoa (Power BI).
  Son schema.sql est la référence commune pour toute l'équipe.
